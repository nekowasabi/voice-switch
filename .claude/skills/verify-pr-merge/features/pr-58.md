# #58 Secret values stay out of the log

`fix: 環境変数が無いときログに秘密の値を出さない` (`gh/cursor/1/head`, ghstack 1/3). Mac `log()` (`Sources/voice-switch/Config.swift:4`) and Windows `Log.Info` / `Log.Fatal` pass every line through `SecretLog.redact`. A `${NAME:-default}` / `${NAME:+x}` always becomes `$NAME`; `${NAME}` and `%NAME%` become `$NAME` when unset; the value (8 characters or more) of any set variable whose name matches `password|passwd|secret|token|api_key|apikey|credential` becomes `$NAME`. SMTP with an empty password throws like a missing one.

## Sub-features

- `sr-wake-ran`: the wake command really ran (`wake.marker`).
- `sr-logged`: the failing command is logged (`command exited 3:`).
- `sr-missing-name`: the missing `${VS_VERIFY_MISSING_TOKEN:-s3cret-value}` is logged as `$VS_VERIFY_MISSING_TOKEN`.
- `sr-set-name`: the set `VS_VERIFY_API_TOKEN` value is logged as `$VS_VERIFY_API_TOKEN`.
- `sr-default-hidden`: `s3cret-value` is nowhere in stdout.
- `sr-value-hidden`: `vsverify-supersecret-42` is nowhere in stdout.

## How to get to it (user POV)

Put a command that names a password variable with a default into the config, leave the variable unset, let the command fail, open the log. The line names the variable, not the value.

## Gotchas

- The redaction runs on every log line and re-reads the whole environment each time. Fine at current log rates; watch it if per-frame logging is added.
- Threshold parity: Swift counts `Character`s (`$0.value.count`), C# counts UTF-16 units (`Length`). They differ only for non-ASCII secret values (未検証).
- A secret that is also an ordinary word in a transcript is replaced in that log line too. Intended.
- Without the PR the same drive prints the raw `s3cret-value` / `vsverify-supersecret-42` (the command string is logged verbatim by `Platform.runCommand:78`). Not re-run as a control.
