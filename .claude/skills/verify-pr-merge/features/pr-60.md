# #60 A keyboard shortcut per action

`feat: 各アクションにキーボードショートカットを付ける` (`gh/cursor/3/head`, ghstack 3/3). `shortcut` on `macOS.actions` / `windows.actions` (same chord names as `pauseShortcut`, e.g. `Control+Shift+F6`). Mac registers with `RegisterEventHotKey` (ids from 100, `MacWakeShortcuts.registerActions`, called once in `AppDelegate`); Windows with `RegisterHotKey` (`WakeLabelHotkey`, ids from `Id + 5`). A press calls `Hotkeys.requestAction(name)`; the listener opens a `Dictation` bound to that action after the same `handoffBusy` / `micInUse` gates as a spoken action, and logs `dictation session: action-hotkey <name> sid=…`.

## Sub-features

- `as-registered-at-launch`: `MacWakeShortcuts.registerActions` is called from `MacApp.swift`.
- `as-session-log`: the `action-hotkey` session path exists in `MacApp.swift`.
- `as-live-press`: MANUAL, a real key press on Mac and Windows.

## How to get to it (user POV)

Add `"shortcut": "Control+Shift+F6"` to an action, restart the app (it is read only at launch), press the chord, speak. The text goes to that action as if its wake word had been heard.

## Gotchas

- `--simulate` does not build `AppDelegate`, so nothing on this Mac registers the hotkey. Only the installed app can prove a press, and the user's running app must be restarted to pick up the config.
- `requestAction` sets `pending = .start`; if no dictation config exists the press is still consumed by the action branch (it does not check `config.cfg.dictation`). Intended for actions, but confirm with a config that has actions and no `dictation`.
- Windows hotkey ids `Id + 5…` must not collide with other `RegisterHotKey` ids in `WakeLabelHotkey` (未検証).
