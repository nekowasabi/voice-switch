# verify-readme-lifecycle

Generated by `/create-verification-skill` for the README and lifecycle change on `feat/readme-lifecycle`. The checklist is [items.md](items.md). The feature map is [features/README.md](features/README.md).

voice-switch is a menu-bar app on macOS and a tray app on Windows. Daily dictation assumes Superwhisper. This skill does not launch either app. A Linux checkout cannot grant Microphone or Accessibility, cannot `open` a `.app`, and cannot attach the Windows tray. The proof on this host is the files and the argument-parsing tests the checklist names.

`live-mac-handtest` and `live-win-handtest` stay `SKIP`. The README must say the human installs the app and runs those hand tests. Do not report a skip as a pass.

## Launch

There is no resident process. Launch means the repo root is this checkout and the script can read it.

```sh
V=.cursor/skills/verify-readme-lifecycle/verify.sh
$V doctor
```

Ready means stdout contains `doctor: ready`. The script does not start `voice-switch`, does not read `~/.config/voice-switch/config.json`, and does not call `osascript` or `explorer.exe`.

Teardown is `$V cleanup`. Run it after a failed drive too.

## Doctor

```sh
$V doctor
```

Doctor is read-only. It passes only when all of these are true.

- `dotnet --list-sdks` prints an 8.x SDK, using `$HOME/.dotnet` when needed.
- `README_ja.md`, `README.md`, `Makefile`, `Info.plist`, `TrayOptions.cs`, `TrayIpc.cs`, `TrayContracts.cs`, `MacApp.swift`, and `PaneRoute.swift` exist.
- This script is executable.
- Every id under a feature file's Sub-features heading is an id in [items.md](items.md), and every items.md id appears in some feature file.
- Each feature file has the four required H2 headings and no others.

Doctor does not require the new README sentences or the new make targets. `drive` does.

## Drive

```sh
$V drive
$V drive daily
```

`drive` with no argument runs every id in [items.md](items.md). `drive <feature>` runs the ids listed in that feature file. Feature names are `daily`, `hand-tests`, `win-lifecycle`, and `mac-lifecycle`.

The harness is this script. It greps the repo and, for `win-parse-tests`, reads the Windows test project that `make win-test` compiles. It does not run the full `dotnet` suite. Run that suite separately when you need its exit code.

A passing id prints `PASS <id>`. A gap this host must not claim prints `SKIP <id> <reason>`. Anything else is `FAIL <id>`. The exit code is 0 only when every selected required id printed `PASS` and the only skips are `live-mac-handtest` and `live-win-handtest`. `SKIP` is not a pass.

Scratch is unused. Evidence goes under `/tmp/voice-switch-readme-lifecycle-verify/evidence/<utc-stamp>/`.

## Evidence

`$V drive` copies stdout and stderr to that evidence directory.

| File | Contents |
|---|---|
| `stdout.txt` | every `PASS`, `FAIL`, and `SKIP` line, then the summary |
| `stderr.txt` | doctor-style errors from the script |
| `exitcode.txt` | process exit code |
| `command.txt` | the `verify.sh` invocation |
| `items.txt` | the feature name, or `all` |

Proof standards:

- A README sentence counts only when the file contains that exact string. A paraphrase fails.
- A log token counts only when the named Swift or C# file still contains it. Do not add a token that the source does not have.
- `win-parse-tests` counts only when the test is registered in `dotnet/VoiceSwitch.Windows.Tests` and the assertions name `TrayOptions.Parse`, `TrayCommand.Quit`, and `TrayCommand.Reload`.
- Makefile proof is the recipe text. Do not run `make start` or `make win-start` here. Those launch an app on a machine this skill does not own.
- `scope-pane-proof` is `git diff` against `origin/main` for `scripts/pane_route_proof.py` only.

## Cleanup

```sh
$V cleanup
```

Cleanup deletes nothing under `evidence/`. It removes `/tmp/voice-switch-readme-lifecycle-verify/scratch` when that directory exists. The drive is foreground and starts no daemon. Cleanup does not kill by process name.

## Helpers

`verify.sh` is the only helper. Invoke it by path from the repo root.

```sh
.cursor/skills/verify-readme-lifecycle/verify.sh doctor
.cursor/skills/verify-readme-lifecycle/verify.sh drive
.cursor/skills/verify-readme-lifecycle/verify.sh drive daily
.cursor/skills/verify-readme-lifecycle/verify.sh cleanup
```

## Maintenance

When the README contract or the lifecycle commands change, update [items.md](items.md) and the feature file in the same change. `/maintain-verification-skill` is the loop for keeping this map honest.
