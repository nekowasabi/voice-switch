# verify-dictation-journal

Generated by `/create-verification-skill` from GitHub issue #49. The checklist is [items.md](items.md). The feature map is [features/README.md](features/README.md).

voice-switch is a menu-bar app on macOS and a tray app on Windows. Issue #49 adds a second store next to the in-memory `DictationHistory` (30 minutes, 50 entries). Each utterance `DictationHistory` accepts is appended to a JSONL file on the device. There is no viewer and no audio file. The user-visible proof is the file on disk, the log line when a path is rejected, and the absence of that line from memory-only expiry.

This harness does not launch the tray or the menu-bar app. Those need a Mac or a Windows desktop, a microphone, and Superwhisper. The production hook under test is `DictationHistory.Add` / `DictationHistory.add` plus `ConfigLoader` / `Platform.expandPath`. The same types the app calls are what the harness calls.

A Linux run is a stand-in. It executes the C# core. It does not boot macOS, so the Swift binary is compiled only when `swiftc` is on `PATH`. It does not apply a Windows ACL. Those two gaps stay unverified until a run on the real machine. Do not report them as passed.

## Launch

There is no resident process. Launch means the harness can build.

```sh
V=.cursor/skills/verify-dictation-journal/verify.sh
$V doctor
```

Ready means stdout contains `doctor: ready`. The script uses `$HOME/.dotnet` when `dotnet` is not already on `PATH`. It does not start the user's installed voice-switch, and it does not read `~/.config/voice-switch/config.json`.

Teardown is `$V cleanup`. Run it after a failed drive too.

## Doctor

```sh
$V doctor
```

Doctor is read-only. It passes only when all of these are true:

- `dotnet --list-sdks` prints an 8.x SDK.
- `Sources/voice-switch/WakeSafety.swift` defines `DictationHistory`.
- `dotnet/VoiceSwitch.Windows.Core/DictationHistory.cs` defines `DictationHistory`.
- `config.example.json` and `config.example.windows.json` exist.
- This script is executable.
- Every id under a feature file's Sub-features heading is an id in [items.md](items.md), and every items.md id appears in some feature file.

Doctor does not require the journal implementation. `drive` does.

## Drive

```sh
$V drive
$V drive append-on-add
```

`drive` with no argument runs every id in [items.md](items.md). `drive <feature>` runs the ids listed in that feature file. The harness is:

```sh
dotnet run --project tests/journal/JournalTests.csproj -c Release --no-restore -- <repo-root>
```

`verify.sh` restores before that run. The test process is one-shot. Its stdout is the proof. A passing id is a line `PASS <id>`. A gap this host cannot execute is `SKIP <id> <reason>`. Any other id, a missing id, or a non-zero exit is a failure. Do not treat `SKIP swift-harness` or `SKIP windows-acl` as a pass.

The feature argument selects a subset. The exit code is still 0 only when every selected required id printed `PASS` and the only skips are the two host skips above.

Scratch files go under `/tmp/voice-switch-journal-verify/scratch/<run-id>/`. The tests must not write `~/Library` or `%LOCALAPPDATA%`.

## Evidence

`$V drive` copies stdout and stderr to:

```text
/tmp/voice-switch-journal-verify/evidence/<utc-stamp>/
```

| File | Contents |
|---|---|
| `stdout.txt` | harness stdout, including every `PASS` / `FAIL` / `SKIP` line |
| `stderr.txt` | build and runtime errors |
| `exitcode.txt` | process exit code |
| `command.txt` | the exact `dotnet run` line |
| `items.txt` | the ids requested for this run |

Proof standards:

- Call `DictationHistory.Add` (C#) or the Swift twin. Writing a JSONL line from the test without going through that type does not prove the hook.
- Assert the file bytes, not a mock callback. Read the JSONL with a new file handle after `Add` returns.
- A second append must leave the first line byte-identical.
- Config path expansion must go through `WindowsPaths.ExpandPath` and the Swift `Platform.expandPath` rules, not a test-local string replace.
- `SKIP` is not a pass. The summary names the host and what a Mac or Windows run still has to do.

## Cleanup

```sh
$V cleanup
```

Cleanup deletes `/tmp/voice-switch-journal-verify/scratch` only. It does not delete `evidence/`. It does not kill by process name. The harness is foreground, so a failed run leaves no daemon. If a `dotnet` child was started in the background by a broken run, cleanup kills the pid recorded in `evidence/<stamp>/pid.txt` when that file exists and the process is still the harness.

## Helpers

`verify.sh` is the only helper. Invoke it by path, from the repo root:

```sh
.cursor/skills/verify-dictation-journal/verify.sh doctor
.cursor/skills/verify-dictation-journal/verify.sh drive
.cursor/skills/verify-dictation-journal/verify.sh drive append-on-add
.cursor/skills/verify-dictation-journal/verify.sh cleanup
```
