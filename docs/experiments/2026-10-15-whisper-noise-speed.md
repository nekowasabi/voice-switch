# Whisper の雑音対策と速度の探索記録（2026-10-14〜15）

Mac 版の自動録音で使う whisper.cpp（`WhisperGate.swift`）について、雑音や咳から口述が通ってしまう問題と、遅さを減らす案を試した記録です。次に同じ探索をするときは、ここを読んでから始めてください。同じ実験を繰り返さないためです。

**Mac 実機は未確認です。** 数字はすべて box（Linux の CPU、4スレッド）で測ったものです。

## 結論

| 案 | 結果 | 理由 |
|---|---|---|
| S1 幻聴の言い回しを一致判定の前に取り除く | **採用**（PR #38） | 雑音の通過が 7/11 から 0/11、held-out で 3/6 から 0/6。声は 4/7 のまま |
| S2 / S2b `audio_ctx` を音声の長さに合わせて小さくする | やめた | 1回の中央値は 28.1秒から7.0秒に縮んだが、雑音の通過が 0/11 から 4/11 に増えた |
| S3 デコードに上限をかけて打ち切る | やめた | 打ち切りまで約23秒かかり、長い口述が途中で切れた |
| S4 平均の対数確率で低い結果を捨てる | やめた | 実際に録った声と雑音で値が重なった |

## 測り方の決まり

次に測るときも、この決まりで数えてください。

1. **アプリでの合否で数える。** アプリは、Whisper と Apple Speech が3文字以上一致したときだけ口述を受け付けます。Whisper の出力だけを数えると判断を誤ります。今回も最初はそれで間違えました。
2. **Apple Speech の出力は3通り仮定する。** box では Apple Speech が動かないためです。
   - 想定A: 何も出さない
   - 想定B: Whisper と同じ文字列を出す（一番悪い場合）
   - 想定C: 元の文を出す（声の音声だけ）

   効果の根拠にするのは想定B だけです。想定A では main も変更後も雑音は 0/11 なので、差が出ません。想定C は Whisper 自身の出力を元の文とみなしているので、根拠になりません。
3. **held-out の音声で確かめる。** しきい値や捨てる言葉のリストを決めたあとに、別の乱数シードで作った雑音（`make_heldout.py`）で確かめます。
4. **時間は3回以上測って、中央値と最小・最大を出す。** box は他の作業と共有なので、ばらつきがあります。

## 前提と環境

- アプリ: whisper.cpp xcframework b5454、モデル `ggml-large-v3-turbo-q5_0.bin`、`language="ja"`、GREEDY、それ以外は初期値（温度のフォールバックあり、`no_speech_thold` 0.6、VAD なし、`audio_ctx` 0、前の呼び出しの文脈を引き継ぐ）。
- box: whisper.cpp **v1.7.5** を CPU でビルド。アプリの b5454 とは版が違います。
- 音声はすべて合成です。声は macOS の `say` で作った TTS、雑音は合成音です。実際に録った音声は英語の JFK だけです（言語を ja に固定しているので、意味の通らない日本語になります）。
- Windows 版は whisper.cpp を使っていないので、対象外です。

## 基準（main、box の CPU、4スレッド、各3回）

- Whisper の出力だけで数えると、雑音11本すべてで何かしらの文が出ます。そのうち8本は決まり文句（「ご視聴ありがとうございました」7本、「音楽」1本）、残り3本（白色・ピンク・ディザー雑音）は「はい」です。
- 0.26秒の「はい」は空になります。whisper.cpp は1秒未満の入力に何も返しません。
- 1回の時間は、音声の長さに関係なく中央値 25.0秒です（30秒にそろえて処理するため）。範囲は約22〜33秒です。
- メモリ（RSS）は、読み込み後 615MB、最初の呼び出しで 951MB、57回後に 1019MB。57回の範囲では増え続ける傾向は見えません。
- `no_speech_prob` は、すべての音声で 0.0 でした。判定には使えません。

## S1 幻聴の言い回しを取り除く（採用）

Whisper の書き起こしから決まった言い回しだけを取り除き、残りの文字で一致を数えます。書き起こし全体は捨てません。

想定B でのアプリの合否です。

| 音声 | main | S1 |
|---|---|---|
| 雑音（基準の11本） | 7/11 通過 | **0/11** 通過 |
| 雑音（held-out の6本） | 3/6 通過 | **0/6** 通過 |
| 声（7本、JFK を除く） | 4/7 通過 | 4/7 通過 |

- 通らない声の3本は、どれも2文字の「はい」です。もともと3文字の下限に届きません。
- held-out で取り除いた3件は、どれも同じ「ご視聴…」でした。
- 速さとメモリは変わりません。
- 弱点: 本当に「今日はご視聴ありがとうございました」と話すと、その発話も捨てられます。
- 観測した幻聴は「ご視聴ありがとうございました」と「音楽」の2つだけです。b5454 では違う言い回しが出るかもしれません。

## S2 / S2b `audio_ctx` を小さくする（やめた）

`params.audio_ctx = min(1500, max(512, samples/320 + 64))` にしました。差分は `patches/s2_audio_ctx.patch` です。

- 1回の時間の中央値は 28.1秒から **7.0秒**（75回）に縮みました。
- ただ、雑音から毎回違う文が出るようになり、S1 のリストで防げなくなりました。想定B での雑音の通過は 0/11 から **4/11** に増えました。

## S3 デコードの上限と打ち切り（やめた）

`no_context = true`、`single_segment = true`、`temperature_inc = 0`、`max_tokens = 48`、10秒で打ち切る `abort_callback` を入れました。差分は `patches/s3_decode_bounds.patch` です（コミットしていない変更から作ったもの）。

| 音声（約30秒） | main | S3 |
|---|---|---|
| 雑音 30秒 | 23.7秒、「ご視聴ありがとうございました」 | 24.9秒で打ち切り、空 |
| 日本語 TTS 約29秒（176文字） | 26.5〜30.5秒、176文字 | 打ち切りありで 22.7秒、空。打ち切りなしで 24.2〜26.1秒、**56文字で途中まで** |

- 10秒で打ち切る設定でも、止まるまでに約23秒かかりました。打ち切りは、重い処理の途中では効きません。
- `max_tokens = 48` で、長い口述が途中で切れました。
- 予定していた200回のループは、S3 をやめたので実施していません。

## S4 平均の対数確率（やめた）

Whisper の出力の平均の対数確率（`avg_logprob`）で、自信の低い結果を捨てる案です。main の各音声の値（1回目）を並べました。

| 音声 | 種類 | avg_logprob |
|---|---|---|
| heldout/single-cough-in-1.2s | 雑音 | -0.0 |
| heldout/brown-5s | 雑音 | -0.0086 |
| silence-3s / silence-10s | 雑音 | -0.0657 |
| real-en-jfk（実際に録った声） | 声 | **-0.0908** |
| hum50-3s | 雑音 | -0.1171 |
| white-3s | 雑音 | -2.2596 |
| TTS の声（6本） | 声 | -0.0007〜-0.0219 |

無音や咳の方が、実際に録った声より高い値になります。どのしきい値でも、雑音を捨てると実際の声も捨ててしまいます。

## 道具

`harness/` に入っています。音声ファイルとモデルは入れていません。

- `make_clips.py`、`make_heldout.py`: 音声を作る（合成なので作り直せます）
- `bench.c`、`bench_seg.c`、`bench_dyn.c`、`bench_s3.c`: アプリと同じ設定で whisper.cpp を呼び、1回ごとに時間、戻り値、RSS、文を JSONL で出す
- `summarize.py`: Whisper の出力だけでの集計
- `app_eval.py`、`app_eval3.py`、`s1_eval.py`: 想定A/B/C でアプリの合否を数える

実行例（box で使った形）:

```
LD_LIBRARY_PATH=wcpp/build/ggml/src ./bench models/ggml-large-v3-turbo-q5_0.bin 4 3 clips/*.wav > runs.jsonl
python3 summarize.py runs.jsonl LABEL
```

## 次の候補

- 速くするには、Whisper の前に声があるかどうかを判定する別の仕組みが要りそうです。`audio_ctx` を小さくするだけでは、雑音の通過が増えます。
- 1秒未満の録音を1秒に伸ばすか、一致なしとして扱う。
- 小さいモデルを2つ目の認識器にする（実際の日本語の声で確かめる必要があります）。
