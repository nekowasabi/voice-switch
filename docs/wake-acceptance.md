# ウェイクの合格条件（#17 S1a）

以下は実装前に定めた提案値であり、実測値ではない。現在実装されている規則は `strict` のみで、未実装の規則をログや集計に追加しない。

- 誤ウェイク頻度（FW/h）は 0.5 以下、かつ同じ条件の strict 基準値との差が +0.1 以下。
- 取りこぼし率（MISS%）は strict 基準値から相対で 30% 以上減少し、各入力状況の取りこぼし件数も増やさない。
- 意図しない貼り付けや外部送信が一度でも起きたら不合格。

比較時は設定とモデルを固定し、規則・入力状況ごとに最低 10 時間の正解ラベル付き負例と 50 回の意図した発話を集める。調整用と評価用のセッションは分ける。計測時間や正解ラベルが不足した場合は判定保留とする。認識件数だけから FW/h や MISS% を算出しない。

`inputIdleSeconds` は Windows の GetLastInputInfo で取得する。0 秒以上 3 秒未満を `after_input`、3 秒以上を `idle`、取得失敗（ログでは -1）・負数・非有限値を `unknown` とする。キーボードとマウスは区別できず、打鍵中かどうかの証明にはならない。

トレイの Ctrl+Shift+F8 は直近 10 秒以内の認識に対して利用者の正解ラベル `wake label: MISS id=N rule=strict inputIdleSeconds=...` を一度だけ記録する。録音開始や配送の許可には使わない。RegisterHotKey が競合した場合は競合をログに記録する。

旧形式の認識行は `missing_fields` に数える。入力停止時間が不明な行を `idle` に含めない。認識本文・読み・代替候補はこの変更で増やさない。

Windows の入力停止取得とホットキー登録は実機で別途検証する。
